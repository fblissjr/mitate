Where data stops and code starts

Drafted 2026-08-02 from the session draft position, the session brief, references/breakdown.md, and the authored surface of plugin/skills/mitate/examples/menagerie.html. Figures carry the command that derives them; prefer re-running to citing.

Exploration, not doctrine. This page argues one side of a design session that is still open. It settles nothing; the decision, when reached, is recorded in docs/representation.md and that file wins wherever the two disagree. An empty decision section there remains a valid outcome.

The question, and the stakes

Where is the boundary between data and code in a mitate scene? Everything else in this design space — what the source artifact is, what the fenced blocks become, what a compiler validates, how a migration runs — is downstream of it.

Two measured costs make it worth deciding now rather than later, and part of this page's argument is that they are different problems:

  • Duplication. 5,704 lines held byte-identical across nine carriers (derived by smoke.js --parity-only, 2026-08-02; grows with every example), policed by a propagation tool, a bracket, a pre-commit hook and a three-glob discipline.
  • Validation in the wrong place. Checks cluster where a mistake is unrepresentable (an unknown name fails a lookup), not where it is expensive (an extent that disagrees with its geometry passes silently). And the static validator that exists, build.js check, reimplements kit semantics with nothing comparing the two models — thirteen open findings share that single root cause (postmortem, 2026-08-02).

The claim

Data is the part of a scene that is decidable without running it. Code is the part that must be run. A function inside a table is not a violation of the line — it is the explicit, typed marker of exactly where decidability ends. The schema around the hole is what makes the ending explicit instead of ambient.

A fact earns the data side when a second consumer — something besides the renderer — uses that decidability: a validator, a solver, a retimer, a recorder, a stager. Every table that exists today passes that test. Nothing was made data for purity's sake, and nothing should be.

Pure literalsBEATS, FRAME, CONFIG, proportion vectors. Fully decidable; validated (unevenly) today.
Tables with resolutionSHOTS — literal rows, anchors resolved against BEATS. Still decidable; check proves it.
Typed holesSUBJECTS.pos, matFor(part) — declared signature, opaque body. Decidability ends here, visibly.
Closed formsbearXAt(t) — named seams shared by data and code, so two consumers cannot disagree.
Authored codebuildWorlds(), animate() — where most of a film's lines live. Reviewable, not decidable.
readable, validatable, diffable as fact
runnable; judged by the three review axes, not by a schema

The foundational form: an invariant plus a movement rule

This is a long-horizon decision, so the thing to record is not an inventory of today's tables — any list is obsolete at the next capability. It is three commitments:

1 · The invariant

Everything on the data side is decidable and validatable without executing a scene. Every place decidability ends is a named, typed hole — never ambient code mixed through the declarations.

2 · The movement rule

The line advances only on measured recurrence (the pattern-ledger's count), and each migration must hand a named second consumer a decision it could not previously make. Films push facts across the line as a side effect of being made — the flywheel, given a direction.

3 · The permanent residue

Some code never migrates, by design. The hand-rolled case is not a backlog of not-yet-data; it is half the reason primitives exist, forever (constraint 4).

Three kinds, not two

The two-sided line hides a third kind that the repo already treats specially: things that are never authored and always regenerable. BEAT{} and TOTAL are forbidden to hand-write today; staged films are derived by stage-films.sh; a future physics bake is the same kind at much larger volume.

authored data

Tables, vectors, declared intent. Written by an author, validated before render, owns the meaning.

derived data

Computed from authored data by a tool at build time: beat spans, durations, staged copies, bakes. Never hand-edited; a check that it is stale is always possible because the deriving command is named.

code

Construction and per-frame motion. Runnable, judged by review. Carries the measured lessons as comments beside the lines they constrain.

Derived data is small today and becomes the largest of the three the day anything is baked. A representation decision with no place for it gets re-litigated then.

Two axes, not one — the cost map

Crossing data/code with kit (fenced, byte-identical in every carrier) versus film (authored per scene) shows the two measured costs live in different cells:

datacode
kit SIZES, the cut-duration table (ride inside fenced blocks) KERNEL · SOLVER · RIG · DRIVER · CHARACTER · CONTRACT · HTML
all 5,704 parity lines live here
film BEATS · STYLE · CONFIG · FRAME · SUBJECTS · SHOTS · proportion vectors
every validation gap lives here		 buildWorlds() add-ons · animate() · helpers (53–172 lines per shipped example, 701 in the corpus fixture; covered by no static check, no parity, no reference)

Consequence — the single most attackable claim on this page: duplication is not evidence that film content should become data. It is evidence that kit code should be emitted rather than replicated. Duplication is solved by a compiler over the kit row (agenda items 2–3); validation is solved by schemas over the film row (question 1 proper). Two separable programs. Either can ship without the other.

Real examples, annotated

All from plugin/skills/mitate/examples/menagerie.html, quoted 2026-08-02.

authored data BEATS — pure literal, two consumers beyond the renderer
const BEATS = [
  {name: 'title',  dur: 2.6},
  {name: 'walk',   dur: 6.2, cap: "1 · Bear, human, strider — one skeleton family"},
  ...
];
Durations, never timestamps — retiming is a one-line edit because accumulation is derived. Read by the retimer, by build.js check (duplicate names, non-positive durations, caption reading speed), and by every anchor resolution. BEAT{}/TOTAL are the derived-data kind: forbidden to author.
typed hole SUBJECTS.pos — data around a declared, opaque function
bear: {pos: t => [bearXAt(t)+bear.centerX, bear.height/2, LANE.bear],
       h: bear.height+.3, w: bear.length, d: 1.6},
The hole has a signature (t → center) and everything around it is decidable without calling it: the solver frames the h/w/d box and never inspects the body; check resolves every name statically. Note h is derived from the built character while d is a hand number — the extent fork below, live in one line.
closed form at a seam bearXAt — one home for a fact, inside one scene
const bearXAt = t => lerp(STARTS.bear, -6.1, ramp(t,'walk',.02,.92));
// SUBJECTS and animate() both derive from THESE, so the camera
// and the bodies can never disagree (proven-walker rule)
The repo's "every fact has one home" rule operating within a scene: a named function shared by the data side (SUBJECTS.pos) and the code side (animate()). Under this draft, this is the canonical boundary shape — not "no functions in tables," not "functions anywhere." Note the latent data visible by inspection: (from, to, beat, window).
code, on purpose animate() — beat-addressed envelopes times authorial taste
const look = pulse(t,'look',.1,.9);          // the ADDRESS is already data
chainCurl(bear.neckChain, -.4*look, 'y');    // the AMPLITUDE is taste
bear.head.rotation.y = -.75*look;
The addressing ('look', the window) is declarative already; the constants are judgment. Extracting -.75 into a table relocates a number without giving any consumer a new decision it can make — the second-consumer test says no, for now. The measured lessons live as comments beside the lines they constrain (tailWag: "amplitudes crossfade, phases never mix"), which a closed vocabulary could not hold.
schema at the seam the proportion vector + matFor — the existence proof
strider = buildCharacter(
  {hipH:3.4, torsoLen:1.4, neckLen:1.8, neckSegs:5, tailLen:2.4, tailSegs:6, ...},
  part => std({torso:0x4e6e8e, head:0x6fa3b7, ...}[part], {roughness:.6}));
// three eyes across the brow — the text said so
for(const k of[-1,0,1]) { ... }
A fixed schema (that throws on impossible bodies) with one typed hole (matFor: part → material, six named parts). From one constructor: a bear, a human, and an invented strider — built deliberately "to keep the anti-template test honest." The three eyes are the permanent residue: the scaffold must say things it did not anticipate.

Hypotheticals — how the line moves, and the one live fork

The move, illustrated: TRAVEL (hypothetical, deliberately not proposed now)

// The same move BEATS made, applied to the latent data in the closed forms:
const TRAVEL = { bear: {from: -16.5, to: -6.1, over: ['walk', .02, .92]} };

The moment this exists, a second consumer exists: check could decide statically that a subject's travel stays inside some shot's coverage for the whole film — undecidable today. But one film's travel pattern is a recurrence count of one; the movement rule says the ledger decides when, not an argument. This is the shape of every future migration: find the latent data, name the second consumer, wait for the count.

The extent fork — a genuine decision this session must make or explicitly defer

The layer's most expensive unvalidated fact: SUBJECTS.h/w/d versus the geometry it claims to describe. Both resolutions are already half-present in the tree, and they pull the boundary in opposite directions:

A · Declare-and-compare

Extents are authored data; probe measures the built geometry; a check compares the two.

for
  • Extents stay statically readable — check can reason about framing without a browser
  • Stays inside probe's existing exception; no new one acquired
  • The declaration remains the author's stated intent, drift becomes detectable
against
  • Needs the runtime for the comparison — the check is not purely static
  • Two sources of truth held in agreement by an instrument, forever

B · Derive-and-dissolve

Extents are computed from construction (as menagerie's h: bear.height+.3 partly does); the check dissolves because the declaration cannot be wrong.

for
  • The defect class becomes unrepresentable — the strongest kind of fix this repo recognises
  • No instrument to run, no drift to police
against
  • Extents stop being statically readable; check loses framing reasoning entirely
  • The fudge terms (+.3, d: 1.6) are authorial intent that derivation cannot produce — so in practice it is a hybrid, and the hybrid needs a rule

This page does not pick. It is the one place the draft finds the boundary genuinely underdetermined by its own test: A treats extents as intent (data), B treats them as consequence (derived data). Which they are is an authoring question the owner decides.

Decisions and tradeoffs

D1 · Typed holes are on the data side

Rejects both alternatives: pure-literal tables (demotes pos/matFor and buys no consumer anything) and functions-anywhere (dissolves decidability).

for
  • Blesses the two shipped patterns that already work
  • Keeps tracking-shots-for-free and material packs
  • Holes are enumerable — a validator can list every point where decidability ends
against
  • A hole is opaque to every static instrument; each one added is surface ceded
  • Needs discipline (or a check) that holes carry declared signatures

D2 · Invariant + movement rule, not a one-time reframe

The line moves by measured recurrence, not by a single architectural migration of geometry and motion into declarations.

for
  • Every migration lands with its consumer and its evidence attached
  • No speculative schema — the "another copy of the code" failure is structurally avoided
  • Matches how BEATS/SHOTS/FRAME actually happened
against
  • Honest counter: if the strategic aim is a deliberate leap — geometry as declarations the way SHOTS did cameras — recurrence-gating is too slow and this decision is miscast as process
  • The ledger must actually be counted, which today is manual

D3 · Derived data is a first-class kind

Named now, before a bake makes it the largest kind. Rule: never authored, always regenerable, deriving command named where the artifact lives.

for
  • The bake proposal slots in without re-litigating the boundary
  • Staleness is always checkable (recompute and compare)
against
  • A third kind is more ontology to hold; the repo currently manages with conventions per-artifact

D4 · The kit is emitted, not replicated

Fenced blocks become build products from one canonical source; the shipped artifact is still one self-contained HTML (invariant 1 is a delivery constraint, satisfied by emission).

for
  • Retires the 5,704-line parity tax and its whole police apparatus (tool + bracket + hook + three-glob discipline)
  • check and the kit read one source — the thirteen-findings class dissolves instead of being bracketed
  • Comments survive: the canonical copy carries them once (constraint 5)
against
  • A compiler is a new load-bearing tool needing its own controls, red-first
  • git diff on an example stops showing the whole artifact — reviewability of the emitted file must be deliberately preserved
  • Migration touches every carrier; sequencing risk is real (see roadmap gate R1)

D5 · Close the open bags

STYLE/CONFIG gain a declared key registry: kit-read keys with shapes and defaults, film-private keys explicitly marked. check warns on unknown keys.

for
  • A misspelled exposure stops rendering-at-default-and-looking-like-a-choice
  • Kit/film namespace collision (a real recorded hazard) becomes detectable
  • Kit-read keys no template declares (flashWidth, cameraFloor) become reachable without reading kit source
against
  • The registry is a list that can drift from the code that reads the keys — it needs a derivation or a control, or it is the six-entry-registry failure again

D6 · The extent fork

Unresolved on purpose — see above. Recorded here so its absence from the decision list is visible rather than silent.

What this means now, and longer term

Now

  • Nothing authored changes hands immediately: today's tables already satisfy the invariant, and today's holes already have signatures.
  • The thirteen open check findings get a strategy instead of a backlog: if D4 proceeds, the class dissolves; the comparison bracket (postmortem forward item 5) is built only if D4 stalls. A trigger, not a preference.
  • The parity apparatus keeps running unchanged until R1's gate is green — no check is relaxed in anticipation.

Longer term

  • At bake time: a bake is derived data, arriving into a slot that already exists. No boundary re-litigation.
  • As state widens ({t, baked}, {t, view}): schema at the seam again; the window contract stays thin and untouched.
  • At agent scale: the boundary is also the line between "checkable by machine, cheaply, always" and "reviewable by judgment, per film" — and the ratio of films to reviewers only grows. That is the real long-term argument for pushing recurring facts across the line.

Roadmap — my read of how we get there

Strangler-shaped, never big-bang. Every step keeps invariant 1 (one self-contained HTML that opens from disk) and both workflows green. Each phase carries its gate in the repo's own idiom; a phase without a red-first control does not ship.

R0

Decide and record

The session reaches (or explicitly defers) the boundary decision and the extent fork; the outcome lands in docs/representation.md's decision section in the owner's words — the boundary as drawn, the cases it cannot hold, what was rejected and why, what would make it wrong.

done if: the decision section is non-empty, or the deferral is recorded with its trigger. Owner's call throughout; this page is one input.

R1

Single-source the kit (the emitter)

The fenced blocks move to one canonical home; a build step assembles scenes from it. First gate is deliberately zero-behavior-change: the emitter must reproduce all nine current carriers byte-identically before anything is allowed to differ. Then carriers flip from hand-maintained to derived, and the parity check inverts — from "nine copies agree with each other" to "every carrier matches emitter output" — before eventually becoming a bracket over the emitter itself.

done if: emission reproduces every carrier byte-for-byte (--parity-only green is then a corollary, not a discipline), and --parity-fix's job description shrinks to "regenerate". refuted if: carriers turn out to need per-film divergence inside fences — that would mean the fences were never really kit, and the whole cost map above is miscarved.

R2

One source for semantics — the thirteen findings, resolved structurally

With the kit single-sourced, build.js check reads the same canonical tables and logic definitions the kit is built from, instead of reimplementing beat accumulation and anchor resolution from memory of them. The open findings close as a class.

done if: the divergence cases from the review (empty SHOTS, subject: [], prototype-named beats, the two-way framing-key mismatch) each resolve identically in check and in a driven page. trigger: if R1 stalls for more than a working week, build the comparison bracket from forward item 5 instead — the class must not stay open on the strength of a plan.

R3

Close the open bags

STYLE/CONFIG key registry, derived from the kit's actual reads (the enumeration in breakdown.md was already produced mechanically — that derivation becomes the registry's source, not a hand-list). check warns on unknown keys; film-private keys get an explicit marker.

done if: a misspelled kit key warns, naming the near-miss; every shipped scene is warning-clean after annotation; the registry is derived or controlled, never hand-held. refuted if: the registry cannot be derived from the reads — then it is another copy of the code and D5 is wrong as specified.

R4

The extent fork, implemented

Whichever way R0 decided: A wires probe's measurement against declared extents (inside its existing exception — read-only, authoring-time, no artifact pipeline); B ships derivation helpers plus the hybrid rule for intent terms. Either way the layer's most expensive gap finally has an instrument or stops being representable.

done if: the corpus fixture gains a deliberately-wrong extent and the chosen mechanism goes red on it, before any shipped scene is touched (red before green, on the corpus, as designed).

R5

Instrument the movement rule

The pattern-ledger's counting becomes cheap enough to actually fire promotion triggers — the flywheel from VISION.md, given its mechanism. TRAVEL is the first candidate watched: the day a second film hand-rolls a travel closed-form, the count says so.

done if: a migration proposal arrives with its ledger count and its named second consumer attached, without a human going looking. refuted if: two more films ship and no fact recurs — then the residue really is all residue, and the line is already in the right place.

R6

Longer term, VISION-gated

The derived-data tier takes its first large occupant (the physics bake, under the proposal's red lines); presentation-time separation makes speed declarative; state widens by named parameters as drivers arrive. None of this is scheduled — it is what the boundary was drawn to survive.

Wrong-if

  • The kit/film cost split is wrong — if any authored film content is inside the parity surface, "two separable programs" collapses back into one.
  • The decidability test cannot sort a full scene inventory — a test that admits everything or nothing is not a boundary.
  • The shipped holes are unrepresentative — if the next film needs holes whose surroundings are not decidable without calling them, D1's condition fails as a rule.
  • The movement rule is too slow for the actual strategic intent — if a deliberate one-time reframe of geometry/motion is the aim, D2 has miscast a strategy question as process.
  • "Render data as code" is about the input side — the film's source material as the data, the scene as its rendering — in which case this page bounds the wrong seam and should be rewritten around input-to-scene.
  • R1's byte-identity gate proves unreachable for a boring mechanical reason (ordering, whitespace) — then the gate softens to "semantically identical + smoke-green", and that softening must be recorded as the first tolerance this project accepted on the artifact path.
