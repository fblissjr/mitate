# Second half — three cold builds come back, and the analysis becomes an instrument

The owner had run three film builds in isolated workspaces overnight and
brought back the scenes, the field reports, the postmortems and the
transcripts. Two are a matched pair on an identical brief — one in an empty
workspace, one in the workspace that had built the market-crash film — and the
third is a video-to-scene attempt. The ask was to learn how an agent uses the
plugin in practice, and to make that a standing feedback loop rather than a
thing the owner has to specify each time.

## The comparison the repo had planned for is unavailable, and saying so first

Three independent no-context subagents reconstructed one build each from its
transcript. Before dispatching them I should have queried model and effort and
did not — the owner had to ask. Queried from the transcripts `(local)`,
2026-08-07: the 2026-08-04 baseline ran **sonnet-5** with no effort field in
its log at all; today's three ran **opus-5** at xhigh, xhigh and high.

That kills the comparison `docs/README.md` had set up. Six axes moved at once —
model, effort, plugin version (0.19.3 → 0.22.1), input modality (text only → a
source image and a source video), duration (37s → 90s), and activation (routed
on the description → explicit slash command). Reference reads went from 2-of-11
to 5-to-8-of-11, which is real and **cannot be credited to the doc work**: a
bigger model at higher effort reading more of everything predicts the same
result. That is now written into the routing row so a future session does not
quietly take the flattering reading.

What the set does supply is one controlled experiment — the turtle pair, same
everything but the workspace.

## What three independent builds hit the same way

Recurrence is the promotion bar, and these cleared it:

- **The scaffold installed outside the workspace, 3 of 3.** `bun add` with no
  local manifest walks UP and installs into the first one it finds. Two
  detected it and spent roughly ten and six minutes recovering, one of them
  editing a manifest and lockfile outside its own workspace; the third never
  noticed and its workspace still has none. `| tail` was not the root cause —
  bun prints `installed three@0.185.1` with no destination either way.
- **`webgpu-stack.md` opened by none of them, during determinism failures in
  all of them.** Roughly 53 minutes across the three rediscovering what that
  file documents. `delivery.md` and `recordings.md` also unopened by all three,
  and all three exported MP4s.
- **All three patched a private copy of `smoke.js`** to see *what* a failing
  determinism arm compared. Three independent reinventions of one missing flag
  on one day.
- **Every builder overstated its own debugging effort**, three of them by six
  to sevenfold. That is the argument for reading transcripts instead of field
  reports, and it is now doctrine.

## The drift question found two live holes

Asked how the new analysis skill avoids going stale, and the question answered
itself twice.

**`selfcheck.js` check 7 derives which docs carry a freshness marker by looking
in a 200-char window** — and a skill's frontmatter `description`, long by
necessity, pushes the marker past it. Two repo skills carried markers nothing
had ever checked; two had never been given one. Silent by construction: a file
outside the population cannot fail. Demonstrated by setting `extract-patterns`
to 2020-01-01 against a 2026-08-05 commit and watching selfcheck stay green.
The window now skips frontmatter, and the first thing it caught was real —
`extract-patterns` had been stale for a week.

Then the harder half: stripping frontmatter fixed the *case* and left the
*class*. A marker below the window still vanished silently. A marker that
exists outside the window is now a failure naming the file.

**`sample.yml` was a fifth consumer of the playwright pin and the only one
nothing compared.** Now checked against `gate.yml`, and its note names any pin
it could not compare rather than reporting a bare agreement count.

All three new checks are bracketed, and each arm was verified to go MISSED with
its fix reverted — not merely CAUGHT with it present.

## The instrument, and the retro that specced it

`.claude/skills/analyze-build-session/` — the second flywheel's tool, and
`VISION.md` now carries the argument beside the pattern flywheel it already
had. It was specced from the retro on this pass rather than from the morning's

~5x high), verify-against-the-current-tree, verify-against-the-code (which
caught a deliberate warning one step from being written up as a false
positive), and recurrence as the promotion bar.

The honest finding about this session's own work: **the first run wrote
subagent-derived claims into a tracked record having spot-checked only the two
that became actionable.** The record now states its evidence tiers instead of
implying one, and the skill makes verify-against-the-subagent the first of four
passes.

Anti-drift design, since no CI check can reach it: repo claims are covered by
`/audit-claims` and now by check 7; schema claims fail loud; **semantic** claims
are the dangerous class and cannot be covered at all — the fixtures are
local-only and a bracket that cannot run from a clean checkout is not a
bracket. So each ships with the one-line command that falsifies it, run per
fixture.
