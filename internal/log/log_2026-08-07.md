## The review agent, verified for the first time

Two owner calls came out of the report. On the ledger: add the missing row, and
verify the file before writing it. On the site: fix the fact tile only, leave

`plugin/agents/film-reviewer.md` had shipped since the plugin had an agent and
had never been audited end to end. It was also the one shipped markdown file
with no row in `docs/shipped-provenance.md`, and the reason generalises: the
0.22.0 scrub's working set was "files carrying a date", and this file carried
none, so it fell out of the batch *and* out of the ledger the batch created.
**A scrub whose file set is what the check matches is narrower than the rule
the check enforces, and the gap is invisible precisely because the check is
green.**

Its first verification found three things:

- **A false mechanism claim.** The brief stated that "both the 0.6 and 0.95
  samples land inside `CONFIG.flashes` windows on the beats bracketing a world
  cut" as a structural property. It is arithmetic dependent on beat length and
  flash half-width. `scenes/crash.html` is the only scene in the corpus that
  declares flashes (`{beat:'halt', at:0, w:.12}`), and the preceding beat's
  `0.95` sample lands 0.175s before the anchor — outside the window. The claim
  is false on the only case that exists. Now stated as the arithmetic to
  compute, with the real common case named.
- **Three reference pointers that dangle from an install cache**, written
  `plugin/skills/mitate/references/...` — which resolves from a clone and from
  nothing else, since the plugin subtree *is* the cache root. Same invariant-3
  class as 0.22.1, and invisible to selfcheck check 5, which resolves markdown
  links rather than backticked paths. The same file used the correct bare form
  two lines below, so it was internally inconsistent.
- **Three amendment narratives that outlived the 0.22.0 scrub** ("this cited a
  repo-local rules file until it shipped", "this line dropped both for four
  versions", "wider than this line once claimed"). The rule is no dates, no
  amendment notes, no decision narratives; check 4 matches ISO dates, so it
  enforces one third of it. Removed.

Landed as **0.22.2** (cascade complete). The ledger now states its row set as a
rule that can be run — one row per line of `git ls-files 'plugin/' | grep
'\.md$'` — rather than a list to be trusted. Verified: 14 files, 14 rows.

## Two owner corrections, mid-session

**Unmeasurable success criteria are deleted, not filed as gaps** (0.22.3).
"Whether a beat is funny, warm, or tense" left `instruments.md`'s ledger. The
framing was the defect: a list titled *what has no instrument* turns each
entry into work someone should do, and an undecidable property has no ground
truth to build an instrument against — so that work cannot fail, which means
it cannot succeed. It also quietly relocates what a corpus film is for. This
bit me directly: I had pitched the film as valuable *because* its success axis
was unmeasurable, which is backwards.

**A film's build class is part of its evidence** (`1afd775`). A film built in
this repo and one built from the installed plugin answer different questions,
and only `crash` said which it was. `scenes/README.md` now defines COLD and
WARM and labels all seven, with the asymmetry stated: a cold build's
smoothness is evidence the docs work; **a warm build's smoothness is evidence
about nothing**, because the builder read the source.
