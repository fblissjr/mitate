## The verification pass

Ran `/verify-written-claims` over `c4f7990..HEAD` — the whole evening batch
(0.21.0, 0.22.0, 0.22.1, the site repair, the conventions commit, the
postmortem). Twelve claims held on re-derivation; nine did not.

The twelve that held are worth recording because they are the reason the
refutations are believable: five shipped brackets repointed in `401c1ed`;
check 2 deriving its scan set from `scenes/` (`selfcheck.js:34,95-101`);
`bracket-parity` at 33 arms; seven staged films; 14 shipped markdown files and
11 references; `crash.html` at 43,518 bytes; `plan.md`'s Examples policy
section carrying its SUPERSEDED banner correctly.

The nine that did not fall into two families, and the families are the finding:

**Half-migration.** `CLAUDE.md` contradicted itself about check 4 eight screens
apart — invariant 2 still described the provenance header that 0.22.0 inverted
away, while the conventions section described the inversion.
`source-of-truth.md` updated its homes table for the same move and left its
rules section asserting the opposite. `representation.md` counted five shipped
examples, of which there are now none, and survived because a
`<!--count-mention-->` marker exempts a line from the scanner without exempting
it from being false. A two-section document invites this: the edit lands where
the writer was looking.

**Same-day invalidation.** The three.js vendoring Open question was filed on
2026-08-05 with a measured basis (`scenes/` at 4.5 MB, five films, four copies
of the IIFE), and 0.21.0 moved `gearbox` into `scenes/` *later the same
evening*. Re-derived: 5,792,858 bytes across six films, 5,749,340 of it five 3D
films. Worse than a stale number — the question's *hardest* design constraint,
"the shipped example must reach installed users runnable with no toolchain,
`plugin install` is a copy, no build step exists to inject at", stopped existing
in that same commit. The question is materially easier than it was written to
be, and nobody would have known without re-reading it. This is exactly the
shape `/verify-written-claims` step 5 exists for, and it is the third time the
repo has caught it.

Also: the changelog promoted a mid-scrub reading of "26 dated lines" to a
before-and-after figure — the pre-scrub tree carried **40**, across 12 files. A
backlog item still asked for a line in a README deleted at 0.21.0. And the
site's fact tile claimed "three.js embedded" per film on a page that cards a

## The review agent, verified for the first time

Two owner calls came out of the report. On the ledger: add the missing row, and
verify the file before writing it. On the site: fix the fact tile only, leave
the title and meta as positioning.

`plugin/agents/film-reviewer.md` had shipped since the plugin had an agent and
had never been audited end to end. It was also the one shipped markdown file
with no row in `docs/shipped-provenance.md`, and the reason generalises: the
0.22.0 scrub's working set was "files carrying a date", and this file carried
none, so it fell out of the batch *and* out of the ledger the batch created.
**A scrub whose file set is what the check matches is narrower than the rule
the check enforces, and the gap is invisible precisely because the check is
green.**

Its first verification found three things:

- **A false mechanism claim.** The brief stated that "both the 0.6 and 0.95
  samples land inside `CONFIG.flashes` windows on the beats bracketing a world
  cut" as a structural property. It is arithmetic dependent on beat length and
  flash half-width. `scenes/crash.html` is the only scene in the corpus that
  declares flashes (`{beat:'halt', at:0, w:.12}`), and the preceding beat's
  `0.95` sample lands 0.175s before the anchor — outside the window. The claim
  is false on the only case that exists. Now stated as the arithmetic to
  compute, with the real common case named.
- **Three reference pointers that dangle from an install cache**, written
  `plugin/skills/mitate/references/...` — which resolves from a clone and from
  nothing else, since the plugin subtree *is* the cache root. Same invariant-3
  class as 0.22.1, and invisible to selfcheck check 5, which resolves markdown
  links rather than backticked paths. The same file used the correct bare form
  two lines below, so it was internally inconsistent.
- **Three amendment narratives that outlived the 0.22.0 scrub** ("this cited a
  repo-local rules file until it shipped", "this line dropped both for four
  versions", "wider than this line once claimed"). The rule is no dates, no
  amendment notes, no decision narratives; check 4 matches ISO dates, so it
  enforces one third of it. Removed.

Landed as **0.22.2** (cascade complete). The ledger now states its row set as a
rule that can be run — one row per line of `git ls-files 'plugin/' | grep
'\.md$'` — rather than a list to be trusted. Verified: 14 files, 14 rows.

## The bracket artifact, filed on its third sighting

`bracket-selfcheck.js`'s cascade arm reported MISSED during the pre-commit run.
It is the documented pending-bump artifact: check 11 diffs against the last
commit touching `plugin.json`, so an uncommitted bump already satisfies it and
the injected violation has nothing to prove. Committed, re-ran, arm went to
CAUGHT — all 4 repo-side brackets green (12+4+30+3 arms).

Filed rather than diagnosed a third time. It is disclosed in the arm's own
comment, but the disclosure lives in the source while the surface prints *"Do
not trust it until this is 0"*, and a cascade commit is exactly when someone
runs it. Observed 2026-08-02, mid-batch 2026-08-05, and today. The fix shape —
detect the pending-bump state and SKIP with the reason stated — is a change to
what a control reports, so it goes through `controls.md`'s door. Row is in
`working-plan.md`'s deferred table with its trigger.
