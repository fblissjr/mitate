## Findings

`Finding:` **`Function.prototype.toString()` under Bun returns a re-print of the
parsed AST, not source text.** `const p = ctx.page, d = ctx.dur;` comes back as
`const { page: p, dur: d } = ctx;` — a destructuring pattern that was never
typed. Consequence, found the hard way: the first mutant written to prove the
new cross-check red **came back green**, because Bun had normalised the mutation
into the very shape the guard looks for. That mutant was not a mutation. It is
now an arm of `bracket-driver.js` expecting exit 0, so if Bun ever stops
normalising, the arm goes red and says what changed.

`Finding:` **Bun also merges adjacent `const` declarations** into one declarator
list, so `const {...} = ctx;` followed by `const frames = [];` re-prints as
`const {...} = ctx, frames = [];`. A regex anchored on the semicolon
false-redded `checkDeterminism` the moment it was written. The guard was right
that it could not read the pattern and wrong about why — which is the failure
mode worth remembering, because a tripwire firing for the wrong reason reads
exactly like one firing for the right one.

`Finding:` **the C4 defect is worse than the plan said.** `working-plan.md` had
"a check computing against `undefined` will often still emit something
plausible." Measured, by moving the setup assignment after the advisory loop:
one correct scene drew a hard `render is 100.0% near-black` while
`checkFramingInvariance` went **silently all-clear on the same run** — every
window shape sampled at NaN is identical, and a check comparing a frame against
itself cannot fail. Confidently wrong on one arm and quietly powerless on the
other, from one missing key. Both halves of this repo's two favourite failure
modes, from a single `undefined`.

`Finding:` **presence vs definedness was a real fork, not a style choice.** Every
one of the nine corpus scenes exports `window.BEATS`, so `k in ctx` and
`ctx[k] !== undefined` are indistinguishable on the corpus and the wrong one
would have shipped green. Measured against a BEATS-stripped scene: presence
passes with the intended `skipped` warnings; definedness fails a legitimate
scene outright and blames smoke.js for it.

# Sixth sitting — the reachability arms, and a fourth handoff inaccuracy

## What shipped (0.16.58)

Four arms in `bracket-driver.js`. Three force one condition each inside the
determinism trio and require that check's own message; the fourth is the negative
control that gives them teeth. 15 arms total, 0 skipped, ~40s with a browser.

**The negative control is the part that took the thinking.** Three arms that go
red on a forced assertion prove nothing on their own — an arm that would pass
whatever the code did looks identical. So: force the assertion AND route its push
into a local sink. smoke.js then reports `all scenes pass` at exit 0 with the
message absent, which is exactly what the three would go red on. That mutation is
now an arm rather than a sentence, which also keeps it off the
measurement-assertion ratchet.

A cruder disconnection — dropping `fails` from the destructure — turned out to be
caught at module load by the requires guard. Found by trying it, not by reasoning:
the first mutant died with `declared requires [PLAN, dur, fails, page] does not
match the keys it destructures`. So the sink is the shape that survives.

## The fixture cost more than the arms

`SCENE` could not be reused. `checkReloadDeterminism` is guarded by
`!fails.length`, and `SCENE` fails live playback by construction — so forcing the
reload assertion against it produces nothing and reads as a broken arm rather than
as the guard doing this. The arms needed a fixture that passes smoke **outright**.

Two properties were arrived at by running it, both after a failed attempt:

- **It draws its own letterbox instead of using CSS.** `framingReader` maps
  *window* coordinates into the canvas buffer via `canvas.width / innerWidth`, so
  a fixed-size buffer letterboxed in CSS makes the check read a different region
  at every window shape. Measured MAD 30.3 narrow / 34.6 wide against a threshold
  of 8. This is a real scene defect, not a quirk of the check.
- **It draws ~240 deterministic cells.** A flat two-rect frame compressed to 1555
  bytes against a 5760-byte floor — the fixture failed the very blank-frame check
  the third arm exists to force.

## Verified both directions

Green: all 15 arms as specified. Red: with the fixture's playback disabled so
`fails` is non-empty at `SHOT_CHECKS` and the guard skips the reload check, the
reload arm goes **BRACKET FAILED** rather than quietly passing. That is the alarm
Phase R wants before it touches that guard, and it is why the arm is worth more
than the one-off run it replaces.

## A fourth handoff inaccuracy, found while closing the debt

The handoff said the reachability gap was "Recorded as `working-plan.md` bucket D;
not fixed." **It is not in `working-plan.md` at all** — not in bucket D, not
anywhere; the phrases do not appear in the file. It lived in this log (narration)
and in one line of `docs/plan.md`. By this repo's own rule that an unreachable
item does not exist, the debt was filed only in narration while a handoff pointed
readers at a doc that never held it.

That brings the audited handoff to three inaccuracies plus this one, all of the
same kind: a confident pointer or count written in the same sitting as the work,
none of them load-bearing on their own.

`docs/plan.md`'s Phase R section is updated: the oracle is described as a control
rather than as a memory, with the negative control and the guard tripwire named.

## Reload is not update, which cost three reloads to notice

`/reload-plugins` re-reads the local cache; it does **not** re-fetch the
marketplace. The clone sat pinned at `bfae322`/0.16.40 across three reloads while
the owner reasonably expected movement. The commands that actually move it:

```
claude plugin marketplace update mitate     # git-pulls the marketplace clone
claude plugin update mitate@mitate          # installs into the version cache
```

**The plugin id is `mitate@mitate`, not `mitate`.** The bare name fails with
`Plugin "mitate" not found` — and prints that failure while the shell pipeline
still reports success, which is the `| tail` trap again, in a new costume.

# Ninth sitting — Phase R's first unit, and three results that looked right

## What shipped (0.16.61)

The determinism trio, restructured under an oracle that existed first.

**Two decisions were bundled in one `try` and only one had been argued.** "Fail
rather than warn" stays. "Abandon every remaining check" is gone as a blanket
rule — it was never a decision, just what a throw does inside a `try`, and the
trio shared one. What a throw costs is now declared per check (`onThrow`, beside
`requires`) with `abandon`/`continue`/`warn`, mapping onto the three tiers the
code already had while its comments described two. **Undeclared is a hard error,
never a default**, because a default is precisely how the unargued behaviour
arrived. Only `checkBlankFrame` changed policy.

**The `!fails.length` guard is gone too, and it was hiding the worst class of
defect this project has.** `plan.md` recorded the fix as blocked on a red-able
fixture that did not exist; 0.16.58's `CLEAN` fixture made one constructible, so
the blocker fell to the arms rather than to an argument. The fixture carries two
defects at once — a random drawn at load, and a playback loop never started so an
unrelated hard fail lands first. **With the guard, smoke reported only the
playback failure: a scene whose live HTML and recorded MP4 are different films
shipped green on the clause the whole project rests on.**

The asymmetry is the finding. `frames.length` is a real precondition; the check
compares against `frames[0]`. `!fails.length` never was one, because the check
navigates and reloads the page itself. Two halves of one `if` with opposite
justifications, and nobody had separated them in four months.

## Three results that looked right and meant nothing

This is the sitting's real lesson, and all three were caught the same way — by
checking what executed rather than reading the summary line.

1. **A corpus comparison that scanned zero scenes.** The globs reached `smoke.js`
   as one literal string; it refused to report on a partial set, both runs
   produced the same refusal, `diff` said IDENTICAL, and my script printed
   success. **I reported that as the gate being satisfied and had to retract it.**
2. **A corpus comparison whose bundler was broken.** Another process deleted the
   workspace's `node_modules` mid-run, so every template failed
   `[self-contained]`. The scanned-scene guard I had added after (1) *also* lied —
   it counted 11 for 9 scenes, because `ok`/`FAIL` lines are not one per scene.
3. **A control that was 3% flaky.** The guard arm offset a rect by
   `Math.round(loadSeed * 90)` — 32 reachable values, so two loads collided about
   one run in thirty and the arm read WRONG-MESSAGE. Caught only because it failed
   once and passed once with no code change between. It now rotates by a raw
   double. **A control that is right 97% of the time teaches people to re-run it
   until it agrees**, which is worse than not having it.

The third would have shipped if its first run had passed. That is the honest
summary: two of these were caught by a discrepancy, not by diligence.
