## REP2: check executes the canonical store (0.18.0, branch r2-check-reads-store)

The phase's design fell out of the recon: `check` mirrored the kit's beat
accumulation (`span{}`/`anchorAt`/`known()`) and solver lookups, and the
kit's real semantics live in the store's KERNEL (`BEAT{}`, `beat()`,
`beatAt`) and SOLVER (`SIZES`, `subjectExtent`, `solveShot`) plus one piece
of unfenced scene code — the house idiom
`.map(sh=>({...sh,t:beatAt(sh.at[0],sh.at[1])}))` that resolves shot
anchors. So `check` now loads both fences from `fences/` beside the tools
and executes them: KERNEL against sanitized BEATS (unresolved durs enter as
0, warned, an explicit input approximation rather than a semantic one),
SOLVER at load for the empty-SHOTS and match-cut refusals, `solveShot` per
shot for subject/size/empty-subject, with every ERROR quoting the kit's own
throw.

   instruments (`check` and `build.js poster`, which drives the page
